# 09. 上线验收清单与开发规则

## 最低上线验收清单

上线前必须全部通过：

- `docker compose up -d --build` 成功。
- 前台首页可访问。
- 客户注册可用。
- 客户登录可用。
- 管理员登录可用。
- 后台新增产品可用。
- 前台购买真实产品可用。
- 订单真实入库。
- 后台手动充值可用。
- 余额支付可用。
- 后台手动确认支付可用。
- 后台手动开通服务器可用。
- 客户后台查看服务器可用。
- 续费可用。
- 到期任务可运行。
- 过期服务器状态会自动变化。
- 工单可提交和回复。
- 管理员代登录可用。
- 操作日志可查。
- 关键密码不明文存储。
- `.env` 未提交 Git。
- GitHub 仓库包含完整代码和部署文档。

## 开发硬性规则

后续执行开发时必须遵守：

- 不再新增业务假数据到前端组件中。
- seed 数据只能放在后端 seed 脚本里。
- 前端所有业务列表必须来自 API。
- 所有写操作必须经过后端接口。
- 所有需要身份的接口必须鉴权。
- 所有金额变动必须写流水。
- 所有后台关键操作必须写操作日志。
- 所有服务器密码必须加密保存。
- 所有 Docker 运行参数必须通过环境变量配置。
- 每个阶段完成后必须提交 Git。
- 每个阶段完成后必须进行实际运行验收。

## 下一步立即执行项

下一步从阶段 1 开始：

1. 重构目录，把现有前端迁移到 `frontend/`。
2. 新建 `backend/` Express 服务。
3. 接入 Prisma 和 MySQL。
4. 添加 `docker-compose.yml`。
5. 实现 `/api/health`。
6. 配置 Nginx 代理 `/api`。
7. 确认 `docker compose up -d --build` 可运行。

完成阶段 1 后，再进入阶段 2 做真实登录注册。
