# 01. 项目定位与范围

## 项目定位

本项目目标不是静态页面，也不是 UI Demo，而是准备投入运营的主机销售与管理系统。

当前仓库已有 React 页面只能作为界面原型保留，后续必须改造成真实全栈系统：

- 所有核心数据必须落库。
- 登录、注册、权限、订单、服务器、到期、续费必须由后端控制。
- 前端不能再依赖写死数组或 `localStorage` 作为业务数据源。
- Docker 不能只跑静态 Nginx，必须支持前端、后端、数据库和定时任务。
- 不接入云厂商 API、不接在线支付 API，可以采用人工收款、后台确认支付、后台手动录入服务器信息的运营模式。

## 当前版本问题

当前实现只适合作为样式参考，不能运营。

明确缺失：

- 没有后端服务。
- 没有数据库。
- 没有真实客户注册。
- 没有真实客户登录。
- 没有真实管理员登录。
- 没有 Session/JWT。
- 没有权限校验。
- 没有密码哈希。
- 没有订单状态流转。
- 没有余额和财务流水。
- 没有服务器真实入库。
- 没有服务器到期扫描。
- 没有续费逻辑。
- 没有定时任务。
- 没有通知系统。
- 没有工单系统。
- 没有操作日志。
- 没有生产环境变量。
- 没有 Docker Compose。

现有前端中的默认用户、产品、订单、服务器、工单数据都属于假数据，后续开发必须删除或迁移为数据库 seed 数据。

## 第一版运营范围

必须包含：

- 前台官网，香港繁体。
- 客户注册、客户登录、客户退出。
- 客户后台。
- 服务器购买页。
- 客户下单。
- 客户余额支付或提交待付款订单。
- 后台管理员登录。
- 后台产品管理。
- 后台用户管理。
- 后台订单管理。
- 后台财务充值和扣款。
- 后台手动确认支付。
- 后台手动录入服务器信息。
- 客户后台查看已开通服务器。
- 服务器到期时间。
- 续费订单。
- 到期定时任务。
- 站内通知。
- 基础工单。
- 管理员代登录客户。
- 操作日志。
- Docker Compose 一键启动。

## 第一版暂不做

- 不接云服务器自动开通 API。
- 不接在线支付 API。
- 不做复杂多商户。
- 不做复杂 RBAC 菜单权限系统，只保留管理员角色字段和基础权限判断。
- 不做短信接口。
- 邮件接口可以预留，第一版可以只做站内通知。
