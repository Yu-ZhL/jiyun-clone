# 06. 核心业务流程

## 注册登录流程

1. 客户填写用户名、邮箱、密码。
2. 后端校验唯一性。
3. bcrypt 生成密码哈希。
4. 创建用户。
5. 登录后写入 HTTP-only Cookie。
6. 前端通过 `/api/auth/me` 获取当前用户。

验收：

- 数据库能看到新用户。
- 密码不是明文。
- 刷新页面仍保持登录。
- 退出后不能访问客户后台。

## 购买流程

1. 客户在 `/buy` 选择套餐和周期。
2. 后端创建订单，状态为 `unpaid`。
3. 如果选择余额支付，后端检查余额。
4. 余额足够则扣款、写流水、订单改为 `paid`，开通状态改为 `pending`。
5. 余额不足则返回错误。
6. 如果线下付款，则后台手动标记已支付。
7. 管理员录入服务器信息并开通。
8. 客户后台显示服务器。

验收：

- 订单真实入库。
- 余额支付会扣余额并写流水。
- 管理员标记支付后状态变化。
- 管理员开通后客户能看到服务器。

## 手动开通流程

1. 后台进入订单详情。
2. 管理员点击开通服务器。
3. 填写 IP、系统、登录账号、登录密码、到期时间。
4. 后端加密保存服务器密码。
5. 创建或更新服务器记录。
6. 订单开通状态改为 `opened`。
7. 生成客户通知。
8. 写操作日志。

验收：

- 服务器数据真实入库。
- 密码不能明文存储。
- 客户后台能看到服务器。
- 客户收到站内通知。

## 续费流程

1. 客户在服务器详情页点击续费。
2. 选择月付或年付。
3. 创建续费订单。
4. 支付后延长 `expires_at`。
5. 写入 `renewals`。
6. 如果服务器已暂停，续费后恢复为 `running`。

验收：

- 续费订单真实入库。
- 到期时间正确延长。
- 续费记录可查。

## 到期任务流程

定时任务：

- 每天 09:00 扫描 7 天内到期服务器。
- 每小时扫描已到期服务器。
- 每小时取消超过 24 小时未支付订单。
- 每小时清理过期代登录 token。

到期处理：

1. `expires_at` 距当前时间小于等于 7 天，状态更新为 `expiring`，生成提醒通知。
2. `expires_at` 小于当前时间，状态更新为 `expired`。
3. 过期超过配置天数，状态更新为 `suspended`。

验收：

- 可通过修改数据库时间触发到期任务。
- worker 日志能看到扫描结果。
- 客户通知表有提醒记录。
- 客户后台状态同步变化。

## 管理员代登录流程

1. 管理员在用户列表点击“进入前台”。
2. 后端创建一次性代登录 token。
3. 前端跳转 `/login/impersonate?token=...`。
4. 客户端使用 token 换取客户登录态。
5. token 标记为已使用。
6. 记录操作日志。

验收：

- token 只能使用一次。
- 过期 token 不可用。
- 操作日志记录管理员、客户、IP、时间。
